# 贡献指南

感谢您对天枢项目的兴趣！我们欢迎各种形式的贡献，包括代码、文档、测试和反馈。

## 贡献方式

### 报告问题

如果您发现了 bug 或有改进建议，请在 GitHub 上提交 issue。在提交 issue 时，请提供以下信息：

1. 清晰的问题描述
2. 复现步骤
3. 预期行为
4. 实际行为
5. 环境信息（操作系统、Python 版本等）

### 提交代码

1. Fork 仓库
2. 创建功能分支 (`git checkout -b feature/AmazingFeature`)
3. 提交更改 (`git commit -m 'Add some AmazingFeature'`)
4. 推送到分支 (`git push origin feature/AmazingFeature`)
5. 开启 Pull Request

### 代码规范

#### 编码风格

我们遵循 PEP 8 编码规范。请使用以下工具检查代码：

```bash
# 代码格式化
black .

# 代码检查
flake8 .
```

#### 类型注解

尽可能为函数参数和返回值添加类型注解。

#### 文档字符串

为所有公共类和函数添加文档字符串，使用 Google 风格。

### 测试

#### 单元测试

为每个新功能编写单元测试，确保代码的正确性。

#### 集成测试

编写集成测试，验证模块之间的交互。

#### 测试覆盖率

目标测试覆盖率达到 80% 以上。

运行测试：
```bash
python -m pytest tests/
```

### 文档

#### 代码文档

为所有公共接口添加详细的文档字符串。

#### 项目文档

在 `docs/` 目录下维护项目文档，包括：
- 架构文档
- 算法文档
- 评估文档
- 开发指南
- 用户手册

### 分支管理

我们采用 Git Flow 分支管理策略：

- `main`: 主分支，包含生产就绪的代码
- `develop`: 开发分支，包含最新的开发代码
- `feature/*`: 功能分支，用于开发新功能
- `bugfix/*`: 修复分支，用于修复 bug
- `release/*`: 发布分支，用于准备新版本发布

### Pull Request 指南

1. 确保 PR 有清晰的标题和描述
2. 确保所有测试通过
3. 确保代码符合编码规范
4. 确保有足够的测试覆盖
5. 确保文档已更新
6. 请求至少一位团队成员进行代码审查

### 代码审查

所有 Pull Request 都需要经过代码审查才能合并。审查时请注意：

1. 代码质量和可读性
2. 是否符合设计原则
3. 是否有适当的测试
4. 是否有适当的文档
5. 是否有潜在的安全问题

## 发布流程

### 版本号规则

我们采用语义化版本号（SemVer）：
- MAJOR: 不兼容的 API 修改
- MINOR: 向后兼容的功能新增
- PATCH: 向后兼容的问题修正

### 发布步骤

1. 从 `develop` 分支创建 `release/x.y.z` 分支
2. 更新版本号
3. 更新 CHANGELOG
4. 进行最终测试
5. 合并到 `main` 和 `develop` 分支
6. 在 `main` 分支上打标签
7. 发布到 PyPI

## 社区行为准则

我们致力于营造一个开放、友好的社区环境。所有参与者都应遵守以下行为准则：

1. 尊重他人，避免侮辱性言论
2. 提供建设性的反馈
3. 承认并纠正错误
4. 专注于进步和改进
5. 保持包容和开放的态度

违反行为准则的行为将不会被容忍。
