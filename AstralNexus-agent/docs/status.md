# 能力状态与限制

本文是 AstralNexus 当前能力口径的单一入口，状态基于 2026-10-10 的代码。其他文档若与本文冲突，以代码和本文为准。

状态含义：

- **可用**：主执行链路已有实现，可用于本地开发和验证。
- **部分实现**：存在代码路径，但范围、后端或保证有限，不应按完整产品能力宣传。
- **未实现**：仅有概念、字段、预留目录或历史文档描述。

## 能力矩阵

| 领域 | 状态 | 当前边界 |
|---|---|---|
| TaskGraph 规划与补丁 | 可用 | 支持节点、依赖、产物关系和受治理的图补丁。LLM 规划质量仍需验证器约束。 |
| 并行执行 | 可用 | 按就绪节点组成波次并发执行；并发度由运行参数控制。 |
| Governor 与角色 | 可用 | Governor 管理角色实例、执行边界和工作流；角色不是一个固定、不可变的流水线。 |
| 工具系统 | 可用 | 支持注册、发现、schema、审批和调用，以及内置工具、工具集、MCP/技能适配。可用工具取决于环境。 |
| 运行持久化 | 可用 | 每次运行使用 SQLite 保存任务、消息、事实、产物、指标、恢复和约束等信息。 |
| 中断与恢复 | 可用 | 支持暂停/停止、需求变更、断点恢复和协调器所有权保护。异常退出后的可恢复程度取决于最后一次持久化状态。 |
| 节点验证与恢复 | 可用 | 节点结果可进入验证、重试、重规划或治理恢复路径。不能保证所有外部副作用都可自动回滚。 |
| 交付验收门 | 可用 | 可在主流程或 `verify-delivery` 中检查交付候选；规则仍在收敛，验收结果应连同产物一起保留。 |
| Dashboard/Workbench | 可用 | 提供本地运行观察和控制接口；这些路由是内部接口，不是稳定的版本化公共 API。 |
| 模型接入 | 部分实现 | 模型客户端使用 OpenAI-compatible Chat Completions 协议。`provider` 主要用于配置/密钥选择，不代表原生协议适配。 |
| 记忆 | 部分实现 | 运行内有分层内存结构，SQLite facts 可随单次运行持久化；检索以简单匹配为主。没有跨运行学习、向量检索或知识库生命周期。 |
| 资源调度 | 部分实现 | 有 local/edge/cloud 资源描述与租约调度，但主要是逻辑资源决策；不会自动把任务派到真实远端机器或切换模型后端。 |
| 敏感信息治理 | 部分实现 | 任务和上下文可携带敏感度元数据；尚无完整的“敏感任务强制本地执行 + 自动脱敏”执行保证。 |
| 故障注入 | 部分实现 | 可注入节点、工具、资源、内存和需求变更类事件以测试恢复路径；部分类型是事件模拟，不等价于真实组件损坏。 |
| 合成评测 | 部分实现 | `eval` 可生成并运行三类合成场景，适合回归观察；没有成熟的行业 benchmark、基线对比或统计显著性框架。 |
| 插件 | 部分实现 | 存在 native/gate 插件宿主能力；sidecar 独立进程模式未实现。 |
| 命名 benchmark 套件 | 未实现 | `benchmarks/` 仅保留命名空间说明，没有可执行的软件工程、研究报告或故障注入基准包。 |
| 公共服务 API | 未实现 | 没有承诺稳定性的版本化 REST API、公共 health endpoint、鉴权和 HTTPS 部署层。 |

## 已知使用限制

1. `eval` 的 CLI 历史默认场景 `long_research` 当前无生成器。请始终显式使用 `research_project`、`code_refactor` 或 `data_analysis`。
2. 配置文件当前只读取模型相关字段；执行、资源、内存、追踪、Dashboard 等运行策略不能仅靠 YAML 配置生效。
3. API key 来自环境变量，配置文件中的任意密钥字段都不应被视为受支持接口，也不应提交真实密钥。
4. local/edge/cloud 是调度模型中的资源标签与租约，不是可验证的物理部署边界。
5. 故障注入 CLI 会根据当前运行状态选择目标，不能替代针对真实工具、资源和存储故障的集成测试。

## 文档维护规则

- 新功能只有在入口、实现和测试至少三者可以对应时，才标为“可用”。
- 只有字段、类名、空目录或设计草稿时，标为“未实现”。
- 有实现但缺少后端、保证或端到端验证时，标为“部分实现”。
- 示例命令必须对应当前 argparse 参数；评测命令必须显式给出有效场景。
